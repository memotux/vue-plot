# AGENTS.md — `docs/` workspace

> Operating instructions for AI coding agents working inside the `docs/` workspace of the `@memotux/vue-plot` pnpm monorepo.
>
> **Global monorepo rules** (Vue 3 conventions, TS strict, library architecture, release workflow, contribution policy) are defined in the [root `AGENTS.md`](../AGENTS.md) and apply here too. This file covers only what is local to `docs/`.

## What this workspace is

The `vue-plot-docs` private workspace — a static Nuxt 4 + Docus site that documents the library at `../`. Content is Markdown + MDC, rendered by Nuxt UI, and statically generated by `nuxt generate` to `.output/public/`. The library itself (`@memotux/vue-plot`) lives one level up; read the [root `AGENTS.md`](../AGENTS.md) and the [project README](../README.md) before changing anything in this workspace.

User-facing orientation (how to run, what lives where, what sections exist) is in the workspace [README.md](./README.md). This file is the agent counterpart.

## Run the site

From the monorepo root: `pnpm install && pnpm --filter vue-plot-docs dev`.
From this folder: `pnpm install && pnpm dev`.
Dev server: <http://localhost:3000> with HMR for Markdown, MDC, and theme changes.

Scripts: `dev`, `build`, `generate` (static output to `.output/public/`), `preview`.

## Project layout (agent reference)

- `app/` — Nuxt app layer. `app.config.ts` (site metadata + Kanagawa color theme), `app.css`, `app.vue`, `app/components/` (auto-imported custom MDC components — `AppHeaderLogo`, `AppIcon`, etc.).
- `content/` — all Markdown. Three numbered sections: `1.getting-started/`, `2.guide/`, `3.api/`. Each section folder has a `.navigation.yml`.
- `public/` — static assets served at the site root.
- `nuxt.config.ts` — extends `docus`, sets `routeRules` to prerender the top-level routes (`/getting-started`, `/guide`, `/api`), and configures the Shiki highlight theme (`kanagawa-dragon` / `kanagawa-lotus`) under `mdc.highlight.theme`.

## Authoring rules (local to `content/`)

### Section layout

| Section | Folder | Page-title style |
| --- | --- | --- |
| Getting Started | `1.getting-started/` | Noun: `introduction`, `installation`, `setup` |
| Guide | `2.guide/` | Topic: `marks-as-children`, `reactive-data`, `nuxt-integration` |
| API Reference | `3.api/` | Symbol: `vplot`, `mark-components`, `types` |

Numeric file prefixes control sidebar order inside a section: `2.installation.md` follows `1.introduction.md`.

### Frontmatter — required on every page

- Minimum: `title` and `description`.
- Landing and section indexes also set `seo.title` and `seo.description` (used for the rendered `<title>` and meta tags).

### MDC components — `u-` prefix is mandatory

```md
::u-page-hero    ✅ resolves to UPageHero
::page-hero      ❌ fails to resolve
```

Without the prefix Vue cannot resolve the component and the page silently fails to render. Common components: `u-page-hero`, `u-page-section`, `u-page-feature`, `u-page-grid`, `u-page-card`, `u-page-cta`, `u-button`. Full list: <https://ui.nuxt.com>.

### Headings and voice

- H2/H3 use **action verbs**: "Configure Vite", not "Configuration".
- Active voice, present tense.
- Add a file-path label to code blocks: ```` ```ts [vite.config.ts] ````.
- For commands available in multiple package managers, wrap in `::code-group` and show `pnpm` first (the monorepo uses pnpm).

### Markdown style

- No `.markdownlint*` config in the repo — defaults apply. Watch for:
  - **MD060** (table column style consistency): data rows and separator row must use the same style. Use `| col | col |` data with `| --- | --- |` separator.
  - **MD040** (fenced code language): every fence needs a language. Use `text` for plain ASCII trees.
- No ESLint / Prettier is configured — do not add them here without asking.

## Theming

The site uses a Kanagawa palette configured in `app/app.config.ts`:

```ts
ui: {
  colors: {
    primary: 'dragon-yellow',
    secondary: 'dragon-blue-2',
    // ...
  }
}
```

Code blocks use the `kanagawa-dragon` (dark) and `kanagawa-lotus` (light) Shiki themes — change in `nuxt.config.ts` under `mdc.highlight.theme`. Custom components in `app/components/` are auto-imported by Nuxt and usable in `app.vue` without an explicit import.

## Deployment

Static site: `pnpm generate` → `.output/public/`. The top-level routes (`/getting-started`, `/guide`, `/api`) are prerendered explicitly in `nuxt.config.ts` under `routeRules`. Deployable to any static host (Vercel, Netlify, Cloudflare Pages, GitHub Pages).
